# ControllerTT · 手柄摇杆训练器

面向 FPS 的手柄摇杆熟练度训练工具。用 Godot 4 做的第一人称 3D 训练场，
可以实时调整死区、响应曲线与辅助瞄准，并当场看到这些参数对手感的影响。

和 Aim Lab 这类练枪软件的定位差别：**本项目的主体是手感参数本身，训练场景只是验证参数的手段。**
所以曲线编辑器、摇杆轨迹、辅助瞄准的逐项强度显示这些东西，优先级高于场景种类的丰富程度。

## 快速开始

**玩游戏：双击项目根目录的 `ControllerTT.exe`。** 那是打好包的单文件，不需要安装 Godot。

本机还没有这份 exe 时，用下面的命令打一次（需要 Godot 4.7 标准版，不需要 .NET/Mono 版）：

```powershell
powershell -File scripts\build.ps1         # 打包成可双击的 exe
powershell -File scripts\run.ps1           # 不打包、直接用编辑器运行
powershell -File scripts\run.ps1 -Editor   # 打开 Godot 编辑器
powershell -File scripts\test.ps1          # 跑核心域单元测试
powershell -File scripts\shots.ps1         # 截各个界面的图，用来检查界面有没有被改坏
```

脚本会按 `$env:GODOT` → 常见安装位置 → `PATH` 的顺序找 Godot。
换了安装位置就设一下环境变量 `GODOT`。

> `scripts/` 下的 `.ps1` 都存成**带 BOM 的 UTF-8**。Windows PowerShell 5.1 会按系统代码页
> 读取没有 BOM 的脚本，里面的中文注释会被读坏并导致语法错误。编辑这些文件时别把 BOM 去掉。

## 操作

启动后先进入主菜单：**随机训练**、**场景训练**、**设置**、**退出**。局内按 Esc 打开参数面板（同时暂停），结算页可以再来一局或返回主菜单。

| 手柄 | 键鼠（没手柄时的替代） | 作用 |
|---|---|---|
| 右摇杆 | 方向键 | 视角。**这是被训练的那条链路**，方向键会被模拟成带斜坡的摇杆 |
| 左摇杆 | WASD | 移动。Apex 式的旋转跟枪需要移动输入才触发 |
| 右扳机 | 鼠标左键 | 开火。追踪场景是持续光束，必须按住才计时 |
| 左扳机 | 鼠标右键 | 开镜 |
| 左摇杆 / 十字键 | 方向键 | 菜单中上下选择；设置中左右调整当前值 |
| A | Enter / Space | 确认、切换开关、打开选项 |
| B | Esc | 返回上一级；选项展开时先关闭选项 |
| LB / RB | — | 在设置的四个分页间切换 |
| Start | Esc | 局内暂停并打开或关闭参数面板；主菜单不抢占当前选择 |
| Y | R | 局内快速重开一局 |
| — | F1 | 显示辅助瞄准气泡的实际角度范围 |
| — | 鼠标移动 | 直接控制视角。**绕过整条摇杆管线**，只用于四处看看，不能用来训练 |

## 四个训练场景

| 场景 | 计分 | 考察什么 |
|---|---|---|
| 追踪 | 在靶时间占比 | 摇杆中低速段的控制力。最能体现响应曲线与旋转跟枪的差异 |
| 甩枪 | 命中率 | 大幅位移的落点精度。曲线末段过陡会表现为频繁过冲 |
| 目标切换 | 命中率 | 追踪与甩枪的结合，也用来检验辅助瞄准会不会锁错目标 |
| 精度 | 命中率 | 死区之外最低速段的微操。内死区偏大或曲线前段偏陡都会在这里暴露 |

四个场景共用同一套逻辑，差别全在参数里，所以你可以在「训练场景」页自己捏出介于它们之间的练习。

## 可调的参数

**摇杆**：死区形状（轴向/径向/混合）、内死区、外死区、反死区；响应曲线（线性/指数/S/反 S/自定义贝塞尔，
可分轴或按模长作用）；水平与垂直满偏转速、开镜倍率；转向加速的延迟、时长与倍率；反转、输出平滑。

内置预设：线性 1:1、COD 标准、COD 动态、APEX 经典、APEX 精细瞄准。

**辅助瞄准**：拆成三种互相独立的机制，各自可单独开关与调节。

| 机制 | 效果 |
|---|---|
| 减速 / 粘滞 | 准星扫过目标时降低转速，更容易停在目标上 |
| 旋转跟枪 | 摄像机自动跟随目标的视野角速度，是「自动跟枪」感的主要来源 |
| 磁吸 | 准星被持续拉向目标中心 |

内置预设：关闭、COD 风格（偏「黏」：强减速 + 磁吸）、APEX 风格（偏「跟」：强跟枪但要求移动输入）、仅减速。

> 预设是对各家**公开描述的手感近似**，不是从游戏里逆向出来的精确数值。当作调参起点用。

## 这个工具能告诉你什么

- **曲线图上的实时游标**：推杆时会有一个点沿曲线跑，你能直接看到自己此刻用的是曲线的哪一段。
- **摇杆轨迹**：把最近一段时间的摇杆位置画成一条尾迹，能暴露回中漂移、推杆抖动、
  以及对角方向被死区形状扭曲——这些光看数字或在游戏里凭手感都很难发现。
- **偏转量分布直方图**：统计你的推杆时间落在行程的哪一段。如果 70% 都在前 30% 行程内，
  那么曲线前段就是唯一值得调的地方，边缘段调多少都感觉不到。
- **辅助瞄准的逐项强度**：HUD 上实时显示减速、跟枪、磁吸各自的生效强度，
  让你能分辨「刚才那一枪是我自己压上去的，还是跟枪把准星带过去的」。

## 项目结构

```
core/          纯逻辑，不依赖任何 Godot 节点，可脱离渲染单测
  input/         死区、响应曲线、输入管线编排
  aim/           辅助瞄准的三种机制、命中判定
  stats/         成绩与遥测
game/          3D 场景：玩家、靶机、场次、场地
ui/            HUD、参数面板、曲线编辑器等自绘控件
tests/         核心域单元测试（77 项）
tools/         集成冒烟测试与截图工具
scripts/       启动、测试、截图的 PowerShell 入口
docs/          架构决策与术语表
```

**改代码前先读 [`docs/architecture.md`](docs/architecture.md)。** 其中最重要的一条约束是：
`core/` 下不允许出现 `extends Node`，也不允许引用 `game/` 或 `ui/`。
手感 bug 的表现是「感觉不对」，肉眼几乎无法定位，只有当这些逻辑是纯函数时才能用测试把不变量钉死。

术语请统一用 [`docs/glossary.md`](docs/glossary.md) 里的说法。

## 测试

```powershell
powershell -File scripts\test.ps1
```

分两层，都是无头运行、几秒钟出结果：

**单元测试（77 项，`tests/`）** 只覆盖 `core/`，专门针对那些**出错了也不会崩、
只会让人觉得「手感怪怪的」**的地方：曲线必须单调不减、死区边界必须连续无台阶、
辅助总强度为 0 时必须与关闭完全等价、管线里曲线必须作用在死区归一化之后、
锁定目标不等于产生干预，等等。

**集成冒烟测试（`tools/smoke.gd`）** 把整个游戏真跑一遍，覆盖单元测试够不到的装配与生命周期：
四种场景都能开局、一局到时后玩家确实停下、参数面板正确暂停与恢复、
手感参数热更新且不打断当前场次。

## 已知边界

- 没有后坐力，也没有武器系统。训练目标是摇杆控制，后坐力会污染变量。
- 靶机之间不做遮挡判定，场地是空旷平地。
- 成绩只存本局，没有跨局的趋势记录。
- 参数存在 `user://` 下，退出时自动保存。
